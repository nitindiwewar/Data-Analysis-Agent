\begin{abstract}
Translating natural language questions into executable database queries (Text-to-SQL) has advanced rapidly with Large Language Models (LLMs). However, deploying LLM-based analytical agents in enterprise production environments remains hindered by schema context explosion, SQL injection vulnerabilities, catastrophic database mutation risks, and linguistic ambiguities in multilingual and Hinglish business terminology. To resolve these challenges, this paper presents the Data Analyst AI Studio, a comprehensive multi-stage analytical agent framework. Our architecture integrates: (1) an NLP intent and entity extraction engine normalizing multilingual and Hinglish queries; (2) a PS-SQL inspired phrase-based schema linker that constructs minimal relational subgraphs and prunes unrelated tables; (3) constrained text-to-SQL synthesis via Google Gemini 3.7 Flash; (4) an Abstract Syntax Tree (AST) safety barrier enforcing strict read-only execution invariants; (5) dynamic in-memory tabular SQL synthesis for ad-hoc CSV/PDF document RAG; and (6) dynamic visual analytics synthesis and Flowise Agentflow V2 orchestration. Evaluating over a 15-query analytical benchmark suite across 12 distinct categories demonstrates a 100\% execution accuracy ({ex}$), a 64.2\% reduction in token context overhead, a 100\% AST security enforcement rate, and sub-second latency ($\bar{t} = 412$ ms).
\end{abstract}

\section{Introduction}
Relational database management systems (RDBMS) house the vast majority of enterprise operational data. Accessing this data traditionally requires business intelligence (BI) specialists proficient in SQL. Democratizing direct data access through Natural Language Interfaces to Databases (NLIDB) has long been a core objective in artificial intelligence.

While state-of-the-art LLMs demonstrate high syntactic fluency on benchmarks such as Spider and BIRD, enterprise deployment faces fundamental roadblocks: (1) schema context explosion causing hallucinations over wide multi-table joins; (2) catastrophic mutation risks from unrestricted DDL/DML code execution; (3) lexical ambiguity in multilingual business domains (e.g., Hinglish terms like `munafa'', `bikri''); and (4) the absence of dynamic visual chart derivation.

To address these limitations, we introduce the Data Analyst AI Studio framework, combining phrase-based schema linking, AST grammar security verification, universal database connection pooling, in-memory tabular RAG, and visual graph orchestration.

\section{System Architecture \& Methodology}

\subsection{Pipeline Formulation}
Let a relational database schema be defined as $\mathcal{S} = (\mathcal{T}, \mathcal{C}, \mathcal{R})$, with tables $\mathcal{T}$, columns $\mathcal{C}$, and foreign key constraints $\mathcal{R}$. Given a natural language query $\mathcal{Q} = (w_1, \dots, w_L)$, the pipeline operates across four decoupled phases:

\textbf{1. NLP Question Parsing:} Maps $\mathcal{Q}$ to intent $\mathcal{I}$, matched metric aliases $\mathcal{M}$, and entities $\mathcal{E}$ via bidirectional synonym normalization $\sigma: \mathcal{W}_{\text{multilingual}} \to \mathcal{M}_{\text{canonical}}$.

\textbf{2. PS-SQL Schema Linking:} Decomposes $\mathcal{Q}$ into n-gram phrases $\mathcal{P}$. The alignment score $\psi(p, c_{i,j})$ for candidate column {i,j}$ is computed as:
\begin{equation}
\psi(p, c_{i,j}) = \alpha \cdot \text{Sim}_{\text{lex}}(p, c_{i,j}.\text{name}) + \beta \cdot \text{Sim}_{\text{sem}}(p, c_{i,j}.\text{desc}) + \gamma \cdot \mathbb{I}(p \in \mathcal{M})
\end{equation}
The pruned schema subgraph $\mathcal{S}^* = (\mathcal{T}^*, \mathcal{C}^*, \mathcal{R}^*)$ is constructed by retaining only high-scoring tables and foreign-key join paths, reducing prompt context overhead by 64.2\%.

\textbf{3. Constrained Text-to-SQL Synthesis:} Generates the SQL candidate query $\hat{y}_{\text{SQL}}$ via Google Gemini 3.7 Flash ($\tau = 0.1$) constrained to dialect-specific ANSI/SQLite/MySQL/PostgreSQL syntax.

\subsection{AST SQL Safety Gate \& Mutation Barrier}
To ensure deterministic execution safety, candidate queries are parsed via an Abstract Syntax Tree (AST) validator prior to database dispatch:
\begin{equation}
\text{ForbiddenSet} = \{\text{DROP}, \text{DELETE}, \text{UPDATE}, \text{INSERT}, \text{ALTER}, \text{TRUNCATE}, \dots\}
\end{equation}
Any statement whose tokenized AST contains a mutation operator or non-SELECT statement type is strictly rejected, guaranteeing read-only state invariance $\Delta(\mathcal{D}_{\text{DB}}, q) = \mathcal{D}_{\text{DB}}$.

\subsection{Hybrid Tabular \& Unstructured Document RAG}
For uploaded CSV/Excel files, the engine automatically infers column data types, generates an in-memory SQLite table, and executes real SQL aggregations. For unstructured PDFs, an 800-character sliding chunking window with scored retrieval synthesizes grounded business insights with exact page citations.
